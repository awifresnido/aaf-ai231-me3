# VAD 0.4 s test results

Follow-up profiling: `docs/runbooks/smart-turn-profile-20261101.md`.

Session: 2026-11-01, 10:56–11:02 Asia/Manila, JV801P local audio.
Experiment `vad-0.4-20261101`, initial timing run `7769a4d631`.
Sixteen recognizable spoken requests produced eighteen inference triggers;
two requests generated repeated inference attempts. Audio was not retained
for acoustic annotation, so reported speech end is the VAD timestamp estimate.

## Results

| Measurement | Result |
|---|---:|
| Configured VAD silence | 0.4 s |
| Estimated speech end to inference trigger | Median 1.072 s, range 1.020–3.402 s, 18 inference triggers |
| Reported Smart Turn analysis processing | Median 649 ms, range 615–669 ms, 19 evaluations |
| Last logged ASR chunk to inference | Median 0.769 s |
| Prior 0.8 s session's comparable ASR-chunk proxy | Median 1.276 s, excluding the special initial fallback turn |
| Native speech-end estimate to bot start | Median 8.385 s over 15 responses, range 2.354–25.132 s |

The proxy improved by about 0.51 s, but different utterances and ASR timing
prevent attributing that entire change to VAD. The earlier session lacked
VAD-frame timing, so it cannot supply a controlled acoustic endpointing
baseline. The native end-to-bot timings include endpointing, unlike the earlier
turn-trigger-to-audio reports; their medians must not be compared directly.

For ordinary complete turns, 0.4 s silence plus roughly 0.65 s of analysis
accounted for approximately 1.05 s before routing. Analysis processing is a
reported combined metric; it does not isolate ONNX inference from feature
preparation. The extra delay in the slow replies was downstream.

## Turn integrity

- The blue-color request triggered inference at 10:56:35.577 before the
  final “blue” transcript arrived at 10:56:35.987. It triggered again at
  10:56:36.596. There was one logged light tool completion, so repeated
  inference is established, but duplicate execution is not.
- The music-volume request likewise triggered at 11:00:35.367 and
  11:00:36.118. These late-final/reopened-turn cases require attention before
  decreasing silence further. Similar behavior existed at 0.8 s; this test
  does not prove the smaller threshold introduced it.
- Smart Turn reported INCOMPLETE during pauses in the music-volume request
  and waited for its final phrase. The combined lights/next-song request
  used the existing 3 s fallback, delaying inference to about 3.4 s after
  the last estimated voiced sample.
- ASR substitutions remain visible, for example “brightness” as “brainness.”
  Without retained audio, a missing word cannot be assigned conclusively to
  VAD clipping rather than ASR recognition or the spoken input.

## Telemetry corrections after this test

Broadcasts create upstream and downstream frame siblings, so the original
observer counted each start and VAD stop twice. Analysis above pairs those
siblings rather than treating them as separate utterances. The observer now
records downstream copies only; a regression check covers this.

`UserTurnInferenceCompletedFrame` is emitted after context processing, so its
original `turn_released` label was wrong and could include GLM waiting time.
The endpoint calculations above instead use the original aggregator inference
log timestamp and the preceding VAD-stop timestamp. Instrumentation now labels
that marker explicitly and records `LLMContextFrame` as
`routing_context_ready`. Sixteen tests passed after these corrections, which
were deployed while preserving the 0.4 s VAD setting.

## Recommendation

Keep 0.4 s for now. Next, profile Smart Turn on the Pi and resolve late-final
turn reopening. Then compare 0.4 and 0.2 s with the same paused-number,
short-command, and complex-request samples. The maximum direct silence-gate
reduction from 0.4 to 0.2 is another 0.2 s; it is not worth increasing
premature turns. Jev reliability and slow MCP calls need separate work because
they still dominate the long responses.
